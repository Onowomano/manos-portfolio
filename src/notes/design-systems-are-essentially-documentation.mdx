A few weeks ago I was redesigning a checkout flow and kept running into the
same wall: every "better" version I sketched needed a component that didn't
exist yet in the design system. The fix wasn't more time — it was fewer
options.

Here's what actually helped:

- Reusing existing list rows instead of inventing a new card shape
- Writing the copy before the layout, so the layout had less to hide behind
- Timeboxing exploration to a single afternoon

I wrote more about the general idea in [this piece on design systems as
documentation](https://onowomano.medium.com/design-systems-are-essentially-documentation-and-i-can-explain-a2ae52100afa).

The whole "index by frontmatter" trick that powers this notes list looks
roughly like this:

```js
const frontmatter = import.meta.glob("./*.mdx", {
  eager: true,
  import: "frontmatter",
});
```

Constraints didn't slow the project down. They just moved the hard decisions
earlier, where they were cheaper to make.
